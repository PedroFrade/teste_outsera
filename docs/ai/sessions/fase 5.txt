  Query de intervalos

  WITH wins AS (
    SELECT mp.producer_id, m.year
    FROM movies m JOIN movie_producers mp ON mp.movie_id = m.id
    WHERE m.winner = 1
  ),
  intervals AS (
    SELECT producer_id,
           LAG(year) OVER (PARTITION BY producer_id ORDER BY year) AS
  previous_win,
           year AS following_win
    FROM wins
  ),
  pairs AS (
    SELECT p.name AS producer, following_win - previous_win AS interval,
           previous_win AS previousWin, following_win AS followingWin
    FROM intervals i JOIN producers p ON p.id = i.producer_id
    WHERE previous_win IS NOT NULL
  )
  SELECT * FROM pairs
  WHERE interval = (SELECT MIN(interval) FROM pairs)   -- e MAX para o array
  "max"
  ORDER BY previousWin, producer;

  - O min e o max saem de duas prepared statements com essa mesma CTE, rodadas
    uma vez após a carga. O resultado fica em memória.
  - Como a CTE é repetida, um kind na WHERE evitaria a duplicação. Mantenho duas
    statements pela legibilidade.
  - Vitórias do mesmo produtor no mesmo ano dão intervalo 0. Isso acontece sem
    tratamento extra, porque o LAG pega o par vizinho.
  - Dentro de um mesmo filme o nome do produtor é deduplicado na importação,
    então um filme nunca gera par consigo mesmo.

  Testes

  ano, 1990 a 1991) em min e Matthew Vaughn (13 anos, 2002 a 2015) em max. Há
  também testes de resposta JSON, idempotência e 405 com Allow no DELETE.

  Os cenários usam 8 fixtures novas com resultado calculado à mão. Cada uma
  isola uma regra:
  - Empates: empate em min e em max com produtores diferentes. Uma indicação sem
    vitória não gera par.
  - Pares consecutivos: só contam pares consecutivos, mesmo com as linhas fora
    de ordem. Eve ganha em 1980, 1982, 1990 e 2000, e o par 1980 a 2000 não
    existe.
  - Mesmo produtor: o mesmo produtor aparece em min e em max.
  - Sem repetidos: nenhum produtor com duas vitórias devolve arrays vazios.
  - Mesmo ano: duas vitórias no mesmo ano dão intervalo 0.
  - Formatação: BOM, CRLF, aspas, linha em branco, vírgula de Oxford, espaços
    extras e YES/Yes. Essas regras afetam o resultado, porque são elas que
    separam os nomes dos produtores.
  - Linha inválida: uma linha com ano inválido é ignorada sem derrubar a
    importação.
  - Só cabeçalho: um CSV só com cabeçalho devolve arrays vazios.

  Decisão para você confirmar

  Usei SELECT DISTINCT no resultado. Se um produtor ganha três filmes no mesmo
  ano, o LAG gera duas vezes o mesmo par (1999 a 1999, intervalo 0). Repetir uma
  linha idêntica seria ruído, então ela sai uma vez, e um mesmo produtor
  continua aparecendo mais de uma vez quando os pares empatados são diferentes.

  Na prática isso só importa com três ou mais vitórias no mesmo ano, que o CSV
  oficial não tem. Se você preferir o resultado "cru", é só tirar o DISTINCT e
  ajustar o caso do Lou no teste. Está registrado como D20 no DECISIONS.md.

  Pontos de design (D22 a D27 no DECISIONS.md)

  - Filtros: uma única prepared statement atende todas as combinações, usando
    NULL para o filtro ausente. Um filtro raro varre as linhas a partir do
    cursor, o que é irrelevante neste volume.
  - Ordem dos nomes: a ordem dentro de producers e studios vem do rowid das
    tabelas de ligação e usa ORDER BY dentro do agregado, que exige SQLite 3.44
    ou mais novo. Aqui são 3.54. Se preferir ordem alfabética, é uma troca de
    uma linha.
  - winner: o parâmetro é um enum de string, e não type: boolean, porque a
    coerção do Ajv rejeita 1 e 0 em query string.
